# Сайт Романа Талютина

Главная заменена утверждённым макетом «ТАЛЮТИН» на HTML/CSS/JS. Геометрия фамилии и её вступительная анимация перенесены без изменений: 36 CSS-фрагментов собираются за 3,5 секунды при первом появлении. При `prefers-reduced-motion` и отсутствии необходимых API остаётся неподвижная композиция. Старые телефон, Three.js/esbuild, Blender-исходники, фон бумаги, корневой статический прототип и отдельная копия макета удалены.

`public/index.html` — серверный шаблон; `styles.css` — оформление; `motion.js` — масштабирование и вступление; `app.js` — фильтры и диалог; `registry.js` — общий SSR/client renderer. CSS и JS загружаются отдельными файлами, строгая CSP сохранена. Главная не использует изображения, SVG-иллюстрации, Canvas и внешние шрифты.

Все опубликованные работы и контакты приходят из действующего источника данных. Жёстко заданные карточки и демонстрационные заглушки автономного макета удалены. Статус, личный вклад, разбор и действующие ссылки берутся из публичного DTO. `?work=…&mode=reveal` открывает кейс; без JS его текст и ссылки доступны в серверной странице. При открытии кейса, запуске iframe и возвращении во вкладку данные проверяются снова. Смена/закрытие кейса снимает iframe и отменяет запрос; устаревший ответ не может вернуть прежнюю работу.

Внешний iframe загружается только по нажатию, при `embedAllowed=true` и разрешённом CSP origin. Иначе остаётся ссылка. Dashboard открывается отдельно. Для опубликованного кейса «Точки» без внешнего URL сохранена ссылка `/tochki/`. Самостоятельная игра и турнирный планировщик `/tool.html` сохранены; планировщик — демонстрационный расчёт, не расписание действующего турнира. Постеры работ сохранены для API и прямых публичных ссылок, но главная их не рисует.

В seed девять записей, при первом локальном запуске публичны ЯКС и Dashboard. Редакционные изменения действующего backend, включая разрешённую владельцем публикацию всех девяти кейсов 3 октября, определяют фактический список. Эта замена интерфейса не меняет `show`, контакты, миграции или конфигурацию backend.

## Локальный запуск

Нужен Node.js 22.13 или новее:

```bash
cd ownsite
npm ci
npm test
npm start
```

Откройте `http://localhost:4173/`. Без `DATABASE_URL` используется локальная SQLite `data/portfolio.sqlite` (не коммитится). При первом запуске создаются девять записей; повторный запуск сохраняет внесённые изменения. Миграция редакции `ownsite-cards-2026-09-29-v3` один раз обновляет девять карточек в SQLite/PostgreSQL, скрывает прежние дубли ЯКС, `wb-cards` и `sparrow`, сохраняя их строки. Поэтому в существующей БД могут остаться дополнительные скрытые архивные записи. После применения редакции повторный старт сохраняет ручные изменения `show` и других полей. Она **не переносит** существующие локальные редакционные правки в PostgreSQL автоматически.

Контакты для локальной проверки: `PUBLIC_PHONE` в международном формате `+7...`, `PUBLIC_EMAIL` с реальным адресом владельца. Если переменные заданы, их корректные значения обновляются в базе при следующем старте. Не добавляйте адрес, телефон и пароль БД в Git. Локальный скрипт `scripts/set-contact.mjs` работает только с SQLite.

## Timeweb Cloud: Tg-mcp как бэкенд

Согласованная конфигурация: отдельное приложение сайта из `rtalyutin/Talyutin/ownsite`, API и редакционные данные — модуль портфолио существующего `rtalyutin/Tg-mcp`. Новая БД и отдельное приложение API не требуются. HTML по-прежнему формируется сервером сайта; браузер обращается к своим `/api/works`, а сервер читает публичный API Tg-mcp. MCP-логины и пароль PostgreSQL в приложение сайта не передаются.

### 1. Активировать модуль в Tg-mcp

После проверки и разрешения на выпуск применить изменение Tg-mcp. Сохранить существующие `DATABASE_URL`, `OUTREACH_ENABLED=true` и настройки других модулей. Добавить:

| Переменная | Значение |
| --- | --- |
| `OWNSITE_ENABLED` | `true` |
| `OWNSITE_MCP_CREDENTIAL_ID` | UUID уже разрешённого MCP-доступа владельца; можно не задавать, если есть `DASHBOARD_SNAPSHOT_MCP_CREDENTIAL_ID` |
| `PUBLIC_PHONE`, `PUBLIC_EMAIL` | Необязательные значения начального наполнения; по умолчанию согласованные контакты владельца |

На включении модуль создаёт изолированную схему `ownsite` в существующей PostgreSQL. Пользователю БД необходимы права на создание этой схемы и её объектов. Инициализация транзакционная и защищена advisory lock; повторный запуск не перезаписывает карточки, контакты и `show`. Сбой optional-модуля оставляет прежний Tg-mcp работающим; портфолио при этом недоступно. До переключения сайта проверить `/ownsite/readyz`, `/ownsite/api/works` и `/ownsite/api/contacts` на техническом домене Tg-mcp. Инструкция backend-контракта находится в `Tg-mcp/OWNSITE.md`.

### 2. Настроить приложение сайта

В App Platform использовать репозиторий `rtalyutin/Talyutin`, ветку `main`, Dockerfile, директорию проекта `ownsite`. Сохранить порт `4173` и healthcheck `/healthz`. Для этого приложения связь с PostgreSQL и VPC теперь не нужна: оно обращается к HTTPS API.

| Переменная | Значение |
| --- | --- |
| `PORTFOLIO_API_URL` | `https://rtalyutin-tg-mcp-4776.twc1.net/ownsite` |
| `ALLOW_INDEXING` | Не задавать для проверочного адреса; `1` только после разрешения открыть индексацию |

Dockerfile задаёт `REQUIRE_PORTFOLIO_API_URL=1`. Без URL приложение не подменяет отсутствующий API локальной SQLite. В этом режиме `DATABASE_URL` не используется; API имеет приоритет. Контакты приходят из Tg-mcp; при ошибке их получения показываются утверждённые email, телефон и ссылка VK из макета. Успешный пустой ответ контактов остаётся пустым. URL должен содержать HTTPS и путь `/ownsite`, без MCP-логина, user/password, query и fragment. Секреты не нужны.

### 3. Проверить связку

После разрешённого деплоя проверить `/`, `/healthz`, `/readyz`, `/api/works`, прямые URL карточек и постеры. В начальном наборе публичны `ycs` и `dashboard`, остальные семь скрыты. Dashboard открывается отдельной вкладкой. При отказе API `/` и `/index.html` возвращают 200: фамилия с анимацией, описание, подход и связь остаются доступны; вместо карточек показывается сообщение о временной недоступности портфолио. Работы не берутся из seed или старого кэша. Works и contacts запрашиваются параллельно и могут отказать независимо. `/healthz` остаётся 200, `/readyz` и запросы данных сохраняют 503 при отказе источника работ, без приватных подробностей. После восстановления API каталог возвращается при следующей загрузке или возврате во вкладку. Ограничены время запроса, размер ответа и допустимый DTO; перенаправления запрещены. Сайт не кэширует карточки: скрытие в backend отзывается при следующем запросе, включая постер и планировщик.

### Управление из чата

Разрешённому MCP-логину доступны `ownsite_list_works` и `ownsite_update_work`. Частичная правка имеет форму `{"id":"ycs","patch":{"show":false}}`; другие поля сохраняются. Обратная правка — `show:true`. Публичное API имеет только чтение; произвольные схемы, таблицы и SQL не принимаются. Применение обновления в рабочей БД требует действующего разрешения владельца.

### Совместимость и откат

Без `PORTFOLIO_API_URL` и без требования remote-режима сохраняется прежняя поддержка SQLite/PostgreSQL для локального запуска и отката. Старые таблицы и данные не удаляются и не переносятся автоматически. Модуль нового конструктора наполняется согласованными девятью карточками; текущие редакционные изменения отдельной старой БД при наличии нужно перенести явно до переключения. Для возврата к прежнему DB-режиму потребуется переопределить `REQUIRE_PORTFOLIO_API_URL=0`, настроить `DATABASE_URL` и вернуть старые параметры окружения. Схема `ownsite` сохраняется. Перезапуск Tg-mcp затрагивает доступность данных портфолио.

## Проверка интеграции — 2 октября 2026

Добавлены контрактные тесты server-to-server адаптера: SSR/JSON/контакты, скрытый прямой URL, отказ upstream, небезопасный URL, неправильный DTO, приватные поля, timeout и размер streamed ответа. Локальный cross-repository тест запускается при наличии checkout Tg-mcp:

```bash
TG_MCP_DIRECTORY=/absolute/path/to/Tg-mcp node --test test/tg-mcp-integration.test.mjs
```

Он использует временную PostgreSQL-совместимую PGlite и настоящий общий HTTP gateway. Это локальное подтверждение; оно не доказывает выполненный деплой или подключение к production PostgreSQL Timeweb.
