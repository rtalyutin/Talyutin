# «Посторонним можно» — приложение портфолио

Это единая серверная версия сайта Романа Талютина. Главная сцена и интерфейс восстановлены из проверенного предпросмотра от 29 сентября; ЯрКиберСезон объединяет действующий сайт и Mini App. Ранее добавленный демонстрационный планировщик сохранён по `/tool.html`, отдельно от главной страницы. Планировщик считает олимпийскую сетку для 8/16 команд, 1/2 площадок и матча 45/60 минут. Можно скачать CSV или автономный HTML. Это не расписание текущего турнира.

В начальном наборе **девять** редакционных записей; публичны ЯКС и Dashboard. Dashboard не featured и открывается отдельной вкладкой, поскольку его сервер запрещает iframe. Остальные семь имеют `show=false` до проверки личного вклада, материалов и права показа. API, главная, постеры и планировщик ЯКС соблюдают этот флаг. Публичные контакты берутся из конфигурации приложения; формы сбора заявок нет.

## Локальный запуск

Нужен Node.js 22.13 или новее:

```bash
cd ownsite
npm ci
npm test
npm start
```

Откройте `http://localhost:4173/`. Без `DATABASE_URL` используется локальная SQLite `data/portfolio.sqlite` (не коммитится). При первом запуске создаются девять записей; повторный запуск сохраняет внесённые изменения. Миграция редакции `ownsite-cards-2026-09-29-v3` один раз обновляет девять карточек в SQLite/PostgreSQL, скрывает прежние дубли ЯКС, `wb-cards` и `sparrow`, сохраняя их строки. Поэтому в существующей БД могут остаться дополнительные скрытые архивные записи. После применения редакции повторный старт сохраняет ручные изменения `show` и других полей. Она **не переносит** существующие локальные редакционные правки в PostgreSQL автоматически.

Контакты для локальной проверки: `PUBLIC_PHONE` в международном формате `+7...`, `PUBLIC_EMAIL` с реальным адресом владельца. Если переменные заданы, их корректные значения обновляются в базе при следующем старте. Не добавляйте адрес, телефон и пароль БД в Git. Локальный скрипт `scripts/set-contact.mjs` работает только с SQLite.

## Timeweb Cloud: порядок первого запуска

1. Создайте приватную сеть VPC в выбранном регионе. Затем создайте управляемый кластер **PostgreSQL** в том же регионе и присоедините его к этой сети. Для связи только внутри VPC публичный IP базе не нужен. Включите резервные копии согласно выбранному тарифу. Сохраните имя базы, пользователя, пароль, приватный хост и порт из панели Timeweb.
2. В App Platform создайте **backend-приложение из GitHub**: `rtalyutin/Talyutin`, ветка `main`, Framework **Dockerfile**, «Путь к директории проекта» — `ownsite`. Выберите тот же регион и **ту же приватную сеть при создании приложения**: позднее поменять сеть приложения нельзя. Dockerfile устанавливает зависимости, запускает Node.js 24 на `0.0.0.0:4173` и содержит `EXPOSE 4173`. Отдельные команды сборки и запуска не нужны.
3. В расширенных настройках задайте «Путь проверки состояния» `/healthz`, который проверяет живой HTTP-процесс и не зависит от кратковременной недоступности БД. `/readyz` отдельно проверяет доступность базы и используется для диагностики сайта; успешный статус приложения в панели сам по себе не подтверждает этот путь. Добавьте локальные переменные окружения:

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URL` | `postgresql://USER:PASSWORD@PRIVATE_HOST:5432/DBNAME` с реквизитами **приватного** подключения из панели; спецсимволы в пользователе и пароле кодируются для URL |
   | `PUBLIC_PHONE` | Телефон владельца, например формат `+7XXXXXXXXXX` |
   | `PUBLIC_EMAIL` | Адрес владельца для связи |
   | `ALLOW_INDEXING` | Оставьте незаданной для проверочного адреса; `1` только после решения открыть индексацию |

   `REQUIRE_DATABASE_URL=1` уже задана Dockerfile. Без рабочей PostgreSQL приложение не стартует, вместо того чтобы молча потерять редакционные изменения в контейнерной SQLite. `PUBLIC_PHONE` и `PUBLIC_EMAIL` необязательны; без них секция связи показывает сообщение о настройке. Не задавайте `PORT` со значением, отличным от `4173`, не согласовав его с `EXPOSE`.
4. Запустите деплой. Технический домен появится в панели. Проверьте `/`, `/healthz` (контейнер жив), `/readyz` (доступна БД), `/api/works` (две карточки: `ycs` и `dashboard`; у ЯКС две `links`, у Dashboard `embedAllowed=false`), оба внешних входа, `/tool.html`, CSV и скачанный автономный HTML. На телефоне живой экран открывается в новой вкладке. Если `/readyz` отвечает 503, проверьте приватную сеть, реквизиты и журналы приложения.

Timeweb использует путь к директории проекта как контекст Dockerfile, а сеть приложения выбирается только при его создании. Локальные файлы App Platform не являются постоянным хранилищем; поэтому редакционные данные размещаются в управляемой PostgreSQL. Документация: [Dockerfile и сеть](https://timeweb.cloud/docs/apps/deploying-with-dockerfile), [создание БД](https://timeweb.cloud/docs/dbaas/dbaas-create), [путь проверки состояния](https://timeweb.cloud/docs/apps/healthcheck-path).

## Публикация следующих работ

Новые записи уже засеяны в `works` с `show=false`. После проверки конкретного кейса подключитесь к PostgreSQL доверенным клиентом **из той же приватной сети** (например, с сервера в VPC), дополните проверенные поля и только затем установите `show=true` для нужного `slug`. Встроенный Adminer Timeweb требует публичный IP базы и в описанной выше приватной конфигурации недоступен. Если позднее выберете Adminer, отдельно настройте публичный IP и доступ к нему. Например, запрос для **уже проверенной** записи:

```sql
UPDATE works SET show = TRUE, updated_at = now() WHERE slug = 'stories';
```

Публичные маршруты не предоставляют редакторских команд. Значения `show` и правки базы сохраняются после нового деплоя: начальные записи добавляются без перезаписи существующих. Отключение `show` отзывает публичный кейс и его постеры; для ЯКС также закрывается маршрут планировщика. При удалении `PUBLIC_PHONE` или `PUBLIC_EMAIL` следующий запуск отзывает только контакты, прежде созданные из этих переменных; вручную заданный Telegram не трогается. Резервную копию и решение об индексации держите в контуре Timeweb.
