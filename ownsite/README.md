# Сайт Романа Талютина

Главная заменена утверждённым макетом «ТАЛЮТИН» на HTML/CSS/JS. Геометрия фамилии и её вступительная анимация перенесены без изменений: 36 CSS-фрагментов собираются за 3,5 секунды при первом появлении. При `prefers-reduced-motion` и отсутствии необходимых API остаётся неподвижная композиция. Старые телефон, Three.js/esbuild, Blender-исходники, фон бумаги, корневой статический прототип и отдельная копия макета удалены.

`public/index.html` — серверный шаблон; `styles.css` — оформление; `motion.js` — масштабирование и вступление; `app.js` — фильтры и диалог; `registry.js` — общий SSR/client renderer. CSS и JS загружаются отдельными файлами, строгая CSP сохранена. Оформление главной не использует изображения, SVG-иллюстрации, Canvas и внешние шрифты.

На страницах портфолио (`/`, `/index.html`, включая ссылки на разборы) подключена Яндекс.Метрика **113739633**. `public/metrika.js` содержит предоставленную владельцем инициализацию: Вебвизор, карта кликов, отслеживание ссылок и хеша, точный показатель отказов, `ssr` и `ecommerce: "dataLayer"`. В HTML есть скрытый `noscript`-пиксель. CSP этих страниц разрешает необходимые адреса Метрики и Вебвизора по [документации Яндекса](https://yandex.ru/support/metrica/ru/code/install-counter-csp), сохраняя запрет `unsafe-inline` и `unsafe-eval`. Самостоятельные проекты и выгружаемый планировщик сохраняют свою прежнюю CSP.

При доступном источнике опубликованные работы и контакты приходят из него. При отказе источника работ главная использует согласованную резервную подборку из `public/offline-works.js`: ЯКС, онлайн-запись и «Точки». Каждая резервная карточка — обычная ссылка на проект с `target="_blank"` и `rel="noopener noreferrer"`; клик не открывает диалог и не запрашивает API. Если источник отказывает при открытии обычного кейса, диалог закрывается и показывается резервный каталог. Успешный пустой ответ остаётся пустым; резервная подборка не меняет seed, БД или флаг `show`. В основном режиме статус, личный вклад, разбор и действующие ссылки берутся из публичного DTO. `?work=…&mode=reveal` открывает кейс; без JS его текст и ссылки доступны в серверной странице. При открытии кейса, запуске iframe и возвращении во вкладку данные проверяются снова. Смена/закрытие кейса снимает iframe и отменяет запрос; устаревший ответ не может вернуть прежнюю работу.

Внешний iframe загружается только по нажатию, при `embedAllowed=true` и разрешённом CSP origin. Иначе остаётся ссылка. Dashboard открывается отдельно. Для опубликованного кейса «Точки» без внешнего URL сохранена ссылка `/tochki/`. Самостоятельная игра и турнирный планировщик `/tool.html` сохранены; планировщик — демонстрационный расчёт, не расписание действующего турнира. Постеры работ сохранены для API и прямых публичных ссылок, но главная их не рисует.

В seed девять записей, при первом локальном запуске публичны ЯКС и Dashboard. Редакционные изменения действующего backend, включая разрешённую владельцем публикацию всех девяти кейсов 3 октября, определяют фактический список. Эта замена интерфейса не меняет `show`, контакты, миграции или конфигурацию backend.

## Локальный запуск

Нужен Node.js 22.13 или новее:

```bash
cd ownsite
npm ci
npm test
npm start
```

Откройте `http://localhost:4173/`. Без `DATABASE_URL` используется локальная SQLite `data/portfolio.sqlite` (не коммитится). При первом запуске создаются девять записей; повторный запуск сохраняет внесённые изменения. Миграция редакции `ownsite-cards-2026-09-29-v3` один раз обновляет девять карточек в SQLite/PostgreSQL, скрывает прежние дубли ЯКС, `wb-cards` и `sparrow`, сохраняя их строки. Поэтому в существующей БД могут остаться дополнительные скрытые архивные записи. После применения редакции повторный старт сохраняет ручные изменения `show` и других полей. Она **не переносит** существующие локальные редакционные правки в PostgreSQL автоматически.

Контакты для локальной проверки: `PUBLIC_PHONE` в международном формате `+7...`, `PUBLIC_EMAIL` с реальным адресом владельца. Если переменные заданы, их корректные значения обновляются в базе при следующем старте. Не добавляйте адрес, телефон и пароль БД в Git. Локальный скрипт `scripts/set-contact.mjs` работает только с SQLite.

## Timeweb Cloud: Tg-mcp как бэкенд

Согласованная конфигурация: отдельное приложение сайта из `rtalyutin/Talyutin/ownsite`, API и редакционные данные — модуль портфолио существующего `rtalyutin/Tg-mcp`. Новая БД и отдельное приложение API не требуются. HTML по-прежнему формируется сервером сайта; браузер обращается к своим `/api/works`, а сервер читает публичный API Tg-mcp. MCP-логины и пароль PostgreSQL в приложение сайта не передаются.

### 1. Активировать модуль в Tg-mcp

После проверки и разрешения на выпуск применить изменение Tg-mcp. Сохранить существующие `DATABASE_URL`, `OUTREACH_ENABLED=true` и настройки других модулей. Добавить:

| Переменная | Значение |
| --- | --- |
| `OWNSITE_ENABLED` | `true` |
| `OWNSITE_MCP_CREDENTIAL_ID` | UUID уже разрешённого MCP-доступа владельца; можно не задавать, если есть `DASHBOARD_SNAPSHOT_MCP_CREDENTIAL_ID` |
| `PUBLIC_PHONE`, `PUBLIC_EMAIL` | Необязательные значения начального наполнения; по умолчанию согласованные контакты владельца |

На включении модуль создаёт изолированную схему `ownsite` в существующей PostgreSQL. Пользователю БД необходимы права на создание этой схемы и её объектов. Инициализация транзакционная и защищена advisory lock; повторный запуск не перезаписывает карточки, контакты и `show`. Сбой optional-модуля оставляет прежний Tg-mcp работающим; портфолио при этом недоступно. До переключения сайта проверить `/ownsite/readyz`, `/ownsite/api/works` и `/ownsite/api/contacts` на техническом домене Tg-mcp. Инструкция backend-контракта находится в `Tg-mcp/OWNSITE.md`.

### 2. Настроить приложение сайта

В App Platform использовать репозиторий `rtalyutin/Talyutin`, ветку `main`, Dockerfile, директорию проекта `ownsite`. Сохранить порт `4173` и healthcheck `/healthz`. Для этого приложения связь с PostgreSQL и VPC теперь не нужна: оно обращается к HTTPS API.

| Переменная | Значение |
| --- | --- |
| `PORTFOLIO_API_URL` | `https://rtalyutin-tg-mcp-4776.twc1.net/ownsite` |
| `ALLOW_INDEXING` | Не задавать для проверочного адреса; `1` только после разрешения открыть индексацию |

Dockerfile задаёт `REQUIRE_PORTFOLIO_API_URL=1`. Без URL приложение не подменяет отсутствующий API локальной SQLite. В этом режиме `DATABASE_URL` не используется; API имеет приоритет. Контакты приходят из Tg-mcp; публичный email сайта установлен владельцем в `r.talyutin@gmail.com` и применяется как к полученному email-контакту, так и к резервному. Это сохраняет новый адрес даже при старом значении в backend; рабочая БД Tg-mcp этой правкой не меняется. При ошибке получения контактов показываются утверждённые email, телефон и ссылка VK из макета. Успешный пустой ответ контактов остаётся пустым. URL должен содержать HTTPS и путь `/ownsite`, без MCP-логина, user/password, query и fragment. Секреты не нужны.

### 3. Проверить связку

После разрешённого деплоя проверить `/`, `/healthz`, `/readyz`, `/api/works`, прямые URL карточек и постеры. В начальном наборе публичны `ycs` и `dashboard`, остальные семь скрыты. Dashboard открывается отдельной вкладкой. При отказе API `/` и `/index.html` возвращают 200: фамилия с анимацией, описание, подход и связь остаются доступны; показываются три резервные карточки — ЯКС, онлайн-запись и «Точки». Карточки открывают проекты в новой вкладке, включая режим без JS; попап для резервной подборки не используется. Ссылки ведут на `https://yarcyberseason.ru/`, `https://talyutin.online/` и `/tochki/`. Работы не берутся из seed или старого кэша; общая серверу и браузеру подборка содержит только эти три разрешённых проекта. Works и contacts запрашиваются параллельно и могут отказать независимо. `/healthz` остаётся 200, `/readyz` и запросы данных сохраняют 503 при отказе источника работ, без приватных подробностей. После восстановления API каталог возвращается при следующей загрузке или возврате во вкладку. Ограничены время запроса, размер ответа и допустимый DTO; перенаправления запрещены. Сайт не кэширует карточки: при доступном backend его актуальный ответ, включая скрытие и пустой список, применяется при следующем запросе. Резервные карточки появляются только при ошибке чтения; API, постеры и планировщик не подменяют отказ источника резервными данными.

### Управление из чата

Разрешённому MCP-логину доступны `ownsite_list_works` и `ownsite_update_work`. Частичная правка имеет форму `{"id":"ycs","patch":{"show":false}}`; другие поля сохраняются. Обратная правка — `show:true`. Публичное API имеет только чтение; произвольные схемы, таблицы и SQL не принимаются. Применение обновления в рабочей БД требует действующего разрешения владельца.

### Совместимость и откат

Без `PORTFOLIO_API_URL` и без требования remote-режима сохраняется прежняя поддержка SQLite/PostgreSQL для локального запуска и отката. Старые таблицы и данные не удаляются и не переносятся автоматически. Модуль нового конструктора наполняется согласованными девятью карточками; текущие редакционные изменения отдельной старой БД при наличии нужно перенести явно до переключения. Для возврата к прежнему DB-режиму потребуется переопределить `REQUIRE_PORTFOLIO_API_URL=0`, настроить `DATABASE_URL` и вернуть старые параметры окружения. Схема `ownsite` сохраняется. Перезапуск Tg-mcp затрагивает доступность данных портфолио.

`/php2shell` — отдельная публичная страница внедрения исправлений PHP2Shell для 1С-Битрикс, от 5 000 ₽. Контакты предложения: Telegram `@evieer` и `R.talyutin@gmail.com`. Страница и её ассеты не зависят от API портфолио. Без JavaScript доступны прямые контакты; автоматической отправки и отдельного хранилища заявок нет. Разбор компрометации и восстановление оцениваются отдельно от внедрения патча.

Проверки маршрута, CSP, ассетов и независимости от backend вместе с регрессией API:

```bash
node --test test/php2shell.test.mjs test/remote-api.test.mjs
```

Страница поставляется существующим Dockerfile вместе с `public/`; дополнительных переменных окружения и миграций не требуется. Для отмены публикации удалить блок маршрута и `php2shellFiles` из `server.mjs`, удалить `public/php2shell/` и связанный тест, затем выполнить обычный деплой. Перед откатом сверить актуальную версию, сохраняя последующие независимые изменения.

## ИИКОТ — `/ai-code`

Отдельный публичный лендинг из девяти секций; не обращается к API портфолио. Раздаётся существующим сервером и Dockerfile из того же `ownsite`, дополнительное Vite-приложение и отдельная сборка `dist` не нужны. Для текущего Timeweb-приложения сохраняются репозиторий `rtalyutin/Talyutin`, ветка `main`, директория `ownsite`, порт 4173 и healthcheck `/healthz`.

- Тексты, порядок и якоря: `public/ai-code/index.html`; процесс — `/ai-code#process`, примеры — `#cases`, контакт — `#request`.
- Цвета, сетки и мобильное оформление: `public/ai-code/styles.css`. Тихий неподвижный дождь: `rain.svg`.
- Тайминги, плотность и скорость дождя, разрешение Canvas и пределы взгляда: `public/ai-code/motion/config.js`.
- Состояния `pending → rain → assemble → ready`, завершение при уходе секции, якорях и фокусе: `motion/sections.js`.
- Сборка символов и общий цикл кадров: `motion/glyph-renderer.js`. Цели текста получаются из HTML. Поток падает вертикально всё время сборки: проходя строку, он оставляет конечные символы точно на их местах. Закреплённые символы больше не двигаются и не заменяются случайными; горизонтальных перелётов нет. Все цели сохраняются без прореживания и накапливаются в отдельном Canvas, который освобождается после сборки. Декоративные Canvas и SVG исключены из дерева доступности.
- 3D-модель кота: `motion/cat-model.js` — треугольная геометрия головы, объёмные уши, щёки, нос и глаза, нормали и ASCII-точки на поверхностях. `motion/cat-volume.js` — WebGL: прозрачная геометрия пишет только глубину, затем поверх рисуются символы из прозрачного атласа. Перспектива и буфер глубины скрывают дальние символы; сплошной заливки и внешних 3D-зависимостей нет. Взгляд и небольшой поворот головы: `motion/cat-gaze.js`; без указателя и при уменьшенном движении модель нейтральная. После изменения геометрии запустить `node scripts/build-ai-cat.mjs`: он обновляет SVG-проекцию той же модели для отключённого JS, недоступного WebGL и потери GPU-контекста.
- Инициализация и статичный режим: `main.js`; `boot.js` скрывает только интро до первого кадра и возвращает HTML через 1,8 секунды, если модуль не запустился. При недоступном JS HTML виден сразу; при уменьшенном движении сборка и взгляд отключены.

Проверка перед отправкой: `npm test`, затем `npm run dev` и открыть `/ai-code`. Проверить первый дождь, сборку всех девяти секций только один раз, быстрый скролл, `/ai-code#process`, фокус клавишей Tab, Telegram, взгляд в четырёх направлениях и возврат при уходе курсора. Проверить ширину 360px, смену размера окна, уменьшенное движение, скрытие вкладки и отключённый JavaScript. Публичные тарифы, сбор репозиториев, аналитика и платёжные формы на лендинге не добавлены.

### Коммерческое обновление — 10 ноября 2026

Этот раздел заменяет оффер и правила квалификации редакции под пилот выше. Целевой сегмент: основатель собрал продукт с помощью ИИ, у продукта уже есть платящие клиенты и конкретная проблема изменений, стабильности, данных или передачи на поддержку. Достаточно одной проблемы. Снижение стоимости и рисков — цель работы; числовая экономия, сроки и гарантии сохранности данных не обещаются без согласованного заказа и подтверждений.

Черновик: «Здравствуйте! Пишу с лендинга ИИКОТ. У меня работающий продукт, собранный с ИИ. Хочу обсудить, как подготовить код к передаче разработчикам».
