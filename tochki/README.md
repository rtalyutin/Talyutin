# Точки — игровой экран прототипа

Открыть на сайте: `/tochki/`. Пустой лист 43 × 60, игра против компьютера,
счёт, обычная диагональная штриховка захваченной области, сдача и чистый лист.
На телефоне поле можно двигать пальцем и увеличивать кнопками; «Весь лист»
показывает его целиком по ширине. На клавиатуре: стрелки и Enter.
Расчёт ходов выполняется в отдельном worker, поэтому сложная позиция
не блокирует управление масштабом. Ошибка расчёта сохраняет принятую позицию.

Рабочие файлы продублированы в `ownsite/public/tochki/`: серверное приложение
собирается из `ownsite`, а корневая папка хранит движок, исходники и тесты.
При изменении экрана синхронизировать эти две папки. Сервер отдаёт только
явно перечисленные игровые файлы; тесты, package.json и README не публикуются.

Принятые PNG бумаги и фонов подключены без изменения. Для доставки крупные PNG
хранятся как base64-части до 64 KiB и `assets/packed-assets.json`. Сервер собирает
исходный PNG и проверяет его размер и SHA-256. Это упаковка без изменения байтов,
а не новая версия рисунка; наружу отдаются прежние PNG URL, внутренние части закрыты.
Для простого статического сервера сначала восстановить PNG из частей манифеста.
PNG штриховки повторяется
и обрезается по вычисленному полигону. Точки и контуры рисуются точно по
координатам; светящиеся точки и вспышки из набора не используются, согласно
предыдущему решению о обычной чернильной подаче.

Ядро поля 43 × 60 по ТЗ 0.3. `playHumanTurn` принимает ход человека и
детерминированный ответ компьютера. `playMove` принимает один ход текущей стороны.
Обычный замкнутый контур захватывает чужие точки, возвращает полигон, список
захваченных пунктов и счёт. Пустой домик ждёт входа чужой точки, затем немедленно
становится действующим. Внутри действующей области новые ходы запрещены.
При исчерпании ходов партия завершается по счёту или ничьёй. Сдача сохранена.

Запуск: `cd tochki && npm test` (Node.js, без внешних зависимостей).
Координаты, площадь и счёт вычисляются ядром, а не графикой.

Воспроизводимый профиль точного поиска запускается командой
`npm run profile:capture`. Он сравнивает обычный контур и два плотных локальных
графа на фиксированной лестнице `searchBudget`. Время выводится как наблюдение,
а не как переносимый порог производительности; код результата (`complete` или
`capture-search-limit`) остаётся детерминированным для данной ревизии.

## Геометрия и границы этого этапа

`capture.js` перебирает простые непересекающиеся циклы через новую точку,
отбрасывает пересечение прежних контуров и выбирает единственную максимальную
площадь. Диагональное соседство допустимо; край поля не замыкает цепь.
Вершины и граница не входят во внутреннюю область.

Пока не реализованы вложенность, освобождение, подключение раннего математического окончания
и стратегический компьютер. Эти ограничения указаны прямо на игровом экране.
Полноценная партия и пользовательская приёмка ещё не готовы.

`early-finish.js` уже исполняет точное строгое неравенство D-05 и готовит
консервативный снимок его известных слагаемых. Оно намеренно не завершает
партию: открытая часть D-06 должна определить, какие захваченные точки реально
могут быть освобождены (`C_T`). Подмена этого множества догадкой могла бы
преждевременно отнять достижимую ничью или победу.

Спорные геометрические случаи не получают нового правила из кода:

- `equal-area-contours-pending`: несколько разных максимальных контуров.
- `contour-relationship-pending`: касание, общая граница или вложенность.
- `capture-search-limit`: точный перебор не завершён в технический бюджет.

Эти диагностики возвращают исходное состояние без расходования хода. Это
ограничение прототипа, а не объявление хода запрещённым по правилам. Частичный
перебор не имеет права выбирать меньшую площадь. Перебор может быть дорогим на
плотном поле; до готовой игры нужен производительный решатель и отдельные
позиции D-06. Новая попытка расчёта не должна дублировать уже принятые ходы.

`regions[].state` — `waiting` или `active`; `contour` — упорядоченные вершины,
`captured` — индексы `y * width + x`, `area` — площадь в клетках.
`capturedBy` хранит единственного владельца очка для пункта, `inactive` исключает
захваченную точку из будущих контуров. Входное состояние не изменяется.
